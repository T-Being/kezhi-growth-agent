# 人机分工与执行权限

优化师负责目标、判断和授权；系统负责组织信息、确定性校验与状态跟踪。模型生成的文字不能直接成为广告平台执行请求。

| 环节 | 产品设计中的 Agent 职责 | 人工职责 | 当前实现 |
| --- | --- | --- | --- |
| 理解客户 | 整理经营背景、识别缺口和冲突 | 确认目标、预算和适用条件 | 预置资料及手工记忆编辑 |
| 诊断 | 关联指标与客户记忆，分开事实和假设 | 核实证据和异常原因 | 固定诊断及三个预设追问 |
| 策略 | 生成候选方案并展示约束与风险 | 选择、修改或拒绝建议 | 规则生成预算调整 |
| 确认 | 展示具体账户、前后值、版本 | 对本次具体动作逐次确认 | 交互确认与失效处理 |
| 执行 | 跟踪每项动作，未知先查询 | 处理冲突、授权重试与接管 | 全部模拟，不调用平台 |
| 复盘 | 汇总实际动作和成熟数据，生成经验草稿 | 判断因果限制并确认经验 | 预置观察数据及确认回写 |

## 权限逐级开放

- **A0 建议与登记**：不写广告平台；允许在应用内确认记忆、记录人工执行。
- **A1 逐次确认执行**：真实写入必须绑定批准版本、账户、预算及有效期，另行完成执行安全验收。
- **A2 授权内自动执行**：在 A1 之上增加累计额度、并发控制、撤权、停止和人工接管能力。

上述为拟定产品权限模型。当前原型没有真实登录、角色权限或平台授权，不能以交互按钮代替服务端鉴权。

## 确认失效

修改预算、关键记忆或发现平台配置变化后，应重新校验并确认。状态未知时先核对既有批次，避免盲目重复写入；部分成功时只对未完成动作发起新的确认。生产实现还需幂等键、服务端状态机和平台回读。

经验只有在来源清楚、适用条件明确并经人工确认后才能复用。一次观察到的改善不能直接变成长期因果规律。
