# 产品定义

## 定位

客知增长 Agent 服务于同时管理多个中小广告主的代理商优化师。它围绕客户经营上下文组织诊断、策略、确认与复盘，把散落的信息转化为可引用、可核实、可复用的客户经验。

核心用户是优化师，团队负责人关注质量和交接成本，广告主关注经营结果、预算边界和决策解释。增长建议成立的前提是：目标清楚、数据口径可靠、客户上下文可追溯、动作在授权范围内。

## 用户问题与价值假设

| 问题 | 产品响应 | 需要验证的价值 |
| --- | --- | --- |
| 切换客户时反复找资料 | 统一客户工作区与经营摘要 | 查找和重新理解背景的人时下降 |
| 建议缺少解释，审核成本高 | 事实、记忆来源、假设及具体参数同时呈现 | 无实质修改率和审核效率提升 |
| 个人经验难以交接 | 带来源、有效期和适用范围的客户记忆 | 交接遗漏减少，历史判断可恢复 |
| 执行与复盘断开 | 按方案版本记录动作和观察结果 | 闭环完成率提升，经验不被错误固化 |

这些是产品假设，尚无真实客户试点数据支持。演示中的客户数、ROI 与操作记录不代表业务规模或产品效果。

## 首期服务范围

优先覆盖单一广告平台、经营反馈清晰的电商客户，以只读建议和人工登记为商业试点边界。当前应用通过模拟预算调整呈现交互闭环；“模拟确认执行”不能视为已经具备真实平台写入能力。

完整可演示客户为青禾家居。其余 14 个客户用于展示分类、背景、记忆、复盘与交接；不宣称每个客户都拥有独立策略引擎。素材生产、自动导入、自由模型问答、真实团队协作、CRM 连接仍是后续能力。

## 成立与否的判断

成立需要同时满足建议质量、业务非劣、净工作效率、客户隔离和单位经济门槛。不能只用生成速度、建议采纳率或投放后的 ROI 上涨论证成立。单独验证持续记忆相对于同一基础模型和同等信息范围的增量价值。

若客户任务低频、目标不明确、经营数据不能关联，或新增审核成本抵消节省，应收窄服务范围。跨经营模式复制前需要重新定义目标、反馈和成熟窗口，不能只换提示词。
